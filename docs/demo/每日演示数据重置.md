# 每日演示数据重置部署说明

官网展示环境需要每天回到干净的任务状态。推荐把后端交给 systemd 管理，并用项目自带的 timer 每天 **北京时间 02:00** 自动执行：

1. 检查后端是否在运行、清理配置是否完整；
2. 停止后端；
3. 备份业务库、协同库和文件目录；
4. 按展示模式清理体验数据；
5. 成功后重新启动后端。

清理默认使用 `--showcase` 方案：保留演示账号、组织/角色、字段、组件、业务模板、报表工作室模板、报表类型和规则；只清理任务、协同、审核、通知、生成记录等体验数据。确需连报表工作室模板一起清空时，在命令中额外加 `--clear-report-templates`。

## 1. 前置条件

- 实际 Linux 服务器，已启用 systemd。
- 后端由**一个** systemd 服务管理所有 Node 进程，例如 `cost-report.service`。
- 服务账号不能是 root，服务必须使用 `KillMode=control-group`。
- 后端只使用一份 root 所有的环境文件，例如 `/etc/cost-report.env`。
- 前端构建产物交给 Nginx/Caddy；参考 `server/deploy/nginx.conf`。

示例后端服务（路径和账号换成实际值）：

```ini
[Unit]
Description=Cost report demo backend
After=network.target

[Service]
User=costreport
WorkingDirectory=/srv/cost-report
EnvironmentFile=/etc/cost-report.env
ExecStart=/usr/bin/node server/src/index.js
KillMode=control-group
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## 2. 配置环境文件

把 `server/deploy/demo-reset.env.example` 合并到后端正在使用的环境文件，并填写**绝对路径**：

```bash
COST_REPORT_DEMO_RESET_ENABLED=true
COST_REPORT_DB_PATH=/srv/cost-report/server/data/demo/business.db
COST_REPORT_COLLAB_DB_PATH=/srv/cost-report/server/data/demo/collaboration.db
COST_REPORT_TEMPLATE_DIR=/srv/cost-report/server/data/demo/templates
COST_REPORT_ARTIFACT_DIR=/srv/cost-report/server/data/demo/artifacts
COST_REPORT_BACKUP_DIR=/srv/cost-report/server/data/demo/backups
COST_REPORT_RESET_BACKUP_DIR=/srv/cost-report/server/data/demo-reset-backups
```

环境文件必须由 root 持有，且组和其他用户不可写：

```bash
sudo chown root:root /etc/cost-report.env
sudo chmod 600 /etc/cost-report.env
```

## 3. 先预览，再安装

预览只读取配置和数据库，不停服、不清理：

```bash
cd /srv/cost-report
npm run demo:timer -- \
  --app-dir /srv/cost-report \
  --user costreport \
  --service cost-report.service \
  --environment-file /etc/cost-report.env
```

确认输出包含 `--scheduled --showcase --dry-run` 后再安装：

```bash
sudo /usr/bin/node server/scripts/install-demo-reset.cjs \
  --app-dir /srv/cost-report \
  --user costreport \
  --service cost-report.service \
  --environment-file /etc/cost-report.env \
  --install --confirm-single-backend
```

安装器会先做只读预检，再写入并启用 `cost-report-demo-reset.timer`，不会立刻清理数据。

## 4. 验证

```bash
systemctl list-timers cost-report-demo-reset.timer
systemctl status cost-report-demo-reset.service
journalctl -u cost-report-demo-reset.service --since today
```

第二天也应确认：

- 后端仍在运行；
- 任务、协同房间、生成记录已清空；
- 业务模板和报表模板仍在；
- `COST_REPORT_RESET_BACKUP_DIR` 下生成了 `reset-*` 备份。

手动验证一次（建议在低峰期）：

```bash
sudo systemctl start cost-report-demo-reset.service
```

## 5. 备份与恢复

每次成功清理前会完整备份：

- `business.db`
- `collaboration.db`
- `templates/`、`artifacts/`、`backups/`
- `manifest.json`（含哈希和清理计划）

默认只保留最近 7 次成功备份。恢复时必须保持后端停止，按 `manifest.json` 的原路径整套恢复，不能只恢复其中一个库。

失败处理：

- 预检失败：后端不会停止，修好配置后重试。
- 停服后清理失败：后端保持停止，不会被自动拉起；先看 `journalctl`，再决定回滚备份还是人工修复。
- 数据库提交后文件阶段失败：保留 `business.db.reset-recovery.json` 恢复标记，次日定时任务会拒绝自动重试；核对备份并人工归档该标记后再恢复定时任务。

## 6. 如果服务器是 Windows

当前项目提供的自动安装器只支持 Linux/systemd。Windows Server 可以用“任务计划程序”实现同样流程：

1. 用 NSSM 或 Windows 服务把后端注册为服务（不要用 `start cmd` 常驻）。
2. 创建一个批处理：停止服务 → `node server\scripts\reset-demo.cjs --scheduled --showcase --apply --confirm-offline --retain 7` → 启动服务。
3. 任务计划程序设置为每天凌晨执行，失败时不要自动启动后端，保留现场排查。

无论 Linux 还是 Windows，都不要在后台服务仍连接 SQLite 时执行清理。
