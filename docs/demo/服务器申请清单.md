# 服务器申请清单（官网演示）

## 1. 可直接提交给 IT / 云平台的规格

> **用途**：SpreadJS 成本指标官网演示站。前端静态资源 + Node.js/Express API + WebSocket 协同 + SQLite 文件数据库。
>
> **操作系统**：Ubuntu 22.04 LTS 或 24.04 LTS，x86_64。
>
> **配置**：2 vCPU / 4 GB 内存 / 40 GB SSD（最低 2 vCPU / 2 GB；如果要在服务器上构建前端，建议 4 vCPU / 8 GB）。
>
> **网络**：公网 IPv4；入站开放 `80`、`443`，`22` 仅限公司办公出口 IP；后端端口 `3000` 只监听 `127.0.0.1`，不对外开放。需要支持 WebSocket。建议 5–10 Mbps 以上带宽；录屏较大时优先放 CDN 或对象存储。
>
> **域名与 HTTPS**：一个演示子域名（例如 `cost-demo.example.com`），A 记录指向服务器 IP；配置有效 HTTPS 证书。
>
> **软件**：Node.js 22 LTS、npm、Nginx（或 Caddy）、systemd。无需 MySQL、Redis、GPU，也无需在服务端安装 Chromium。
>
> **目录与备份**：`/srv/cost-report` 作为持久化目录；数据库、报表文件和清理备份都放在持久磁盘；保留每日备份，最好有云盘快照。录屏约 158 MB，作为独立媒体目录或 CDN 资源存放，不打进前端构建产物。
>
> **时区**：`Asia/Shanghai`。

如果服务器部署在中国大陆，域名需要先完成 ICP 备案；如果不想走备案，可申请香港或海外区域，但访问延迟和公司网络策略需要确认。

## 2. 软件层面的要求

- 后端由 **一个 systemd 服务**管理，使用非 root 账号（例如 `costreport`）。
- 服务使用一份 root 所有的环境文件，例如 `/etc/cost-report.env`，权限 `600`。
- 环境文件至少包含：
  - `PORT=3000`
  - `HOST=127.0.0.1`
  - 强随机的 `JWT_SECRET`
  - `COST_REPORT_*` 存储绝对路径
  - 定时清理所需的 `COST_REPORT_DEMO_RESET_ENABLED=true` 等配置
- 前端构建产物由 Nginx/Caddy 托管，`/api` 和 `/collaboration` 反向代理到后端；History 路由必须回退到 `index.html`。
- 上传接口最大 50 MB，反向代理的 `client_max_body_size` 要相应放开；报表准备和上传接口建议 120 秒超时。

## 3. 授权是前置条件（最重要）

当前本地环境变量里的测试授权不能直接用于生产：

- `spreadjsLICENSE`、`designerLICENSE` 是**按域名**授权的，当前绑定 `test.com`。
- `serverLICENSE` 是**按服务器机器**授权的，新服务器需要重新申请。
- 前端授权在**构建时**注入 `dist`，所以必须用生产域名对应的授权重新执行 `npm run build:showcase`。
- 授权只通过环境变量提供：构建机设置 `SPREADJS_LICENSE`、`DESIGNER_LICENSE`，服务器运行时设置 `SERVER_LICENSE`（服务端渲染还需要 `SPREADJS_LICENSE`）。不写入仓库或发布包。

向 SpreadJS 商务/支持申请时，准备：

1. 生产演示域名（精确到子域名，例如 `cost-demo.example.com`）；
2. 生产服务器机器码（按对方提供的采集方式提供）；
3. 项目中实际用到的插件清单：Designer、ReportSheet、PDF、Excel IO、Charts、DataCharts、Shapes、Tables、Slicers、Formula Panel、Collaboration 等；
4. 确认授权覆盖的并发/部署范围。

服务器首次启动协同服务后会生成实例文件；**不要删除该实例文件**，否则机器标识变化会导致授权失效。

## 4. 本地打包与验证

```bash
# 安装锁定依赖
npm ci
npm --prefix server ci

# 确认 SPREADJS_LICENSE / DESIGNER_LICENSE 已设置；准备不参与构建的录屏目录
npm run media:prepare
npm run build:showcase

# 启动后端（本地 server/.env 使用 3001）
cd server && npm start

# 另开终端，预览构建产物；会把 /api、/collaboration 和 /media 代理到本地
cd ..
npm run preview:showcase
```

- `http://localhost:5199` 可验证页面和接口。
- 协同填报请通过 `http://test.com`（Caddy → 5199）访问，因为客户端授权按域名校验。
- 预览前先停止 `npm run dev:showcase`，两者都占用 5199。
- 需要重置本地演示数据时运行 `npm run demo:reset`，默认保留字段、组件、模板和报表模板。

## 5. 部署顺序

1. 申请服务器、域名、HTTPS，并完成授权申请。
2. 在本地用生产授权构建 `dist`，确认能通过 `preview:showcase` 跑完整流程。
3. 准备基线数据：停止后端，运行一次展示模式清理，保留模板和报表模板，清空体验任务；把 `server/data/demo/` 下的 `business.db`、`collaboration.db`、`templates/` 作为初始数据上传（不要上传本地测试产生的报表成果）。
4. 上传代码、`dist` 和基线数据；在运行环境设置授权变量，安装后端生产依赖。
5. 配置 systemd 服务和 Nginx/Caddy，启动后端，验证 `/health`、登录、协同、报表生成。
6. 按 `docs/demo/每日演示数据重置.md` 安装每日 02:00 清理 timer。

## 6. 不需要申请的资源

- 不需要 MySQL/PostgreSQL、Redis、消息队列。
- 展示模式的报表在访客浏览器中生成，服务器不需要 Chromium；只有普通模式的函数试炼场/后端报表才需要 Playwright。
- 不需要 GPU。
