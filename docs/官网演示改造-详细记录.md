## 0. 决策摘要

- **只做一个版本**，不做"极简版 + 复杂版"两套。
- **范围按方案甲**：保留月度主线（模板设计 → 协同填报 → 审核发布 → 报表输出），季度考核整体不做。报表输出由月度报表工作室与月度参考报表体现，季度参考报表不进入演示。
- **引导层采纳**：演示首页、进度条、交接按钮、任务上下文、能力胶囊、术语/错误文案、故事化数据、三状态任务、3/8 分钟路线、结束页、一键重新开始。
- **引导层不做**：查看底层抽屉、首次交互提示、在线状态强化、视频兜底、机器人搭档、自动双窗口。
- **协同体验**：保留现有"分享链接"，只加一句"用另一个账号登录即可体验协同"的提示。
- **汇报材料**：`docs/官网演示汇报.html`。

## 1. 背景

- 代码库最初为矿业、交通投资类客户做的方案，是一套完整的集团多组织报表业务闭环。
- 公司主营 SpreadJS，需要把这个项目改造成官网上的产品演示，让访客理解"SpreadJS 在真实业务系统里能做什么"。
- 现有复杂度（13 个角色码、20+ 页面、5 套状态机、财务术语密集、空库冷启动）不适合官网访客。

## 3. 演示身份与数据

> 2026-11-04 再次清理：保留业务字段目录（7 个字段及其版本/提案），组件、模板、周期包、任务、业务修订、协同房间、报表工作室模板均已删除。下文的演示身份仍然有效；预置数据是**重建时的目标**，不再是当前库状态。

### 3.1 演示身份（4 个）

| 身份 | 角色码 | 用途 |
|---|---|---|
| 设计/管理员 | `system_admin` | 设计并发布模板、配置周期包、查看全部 |
| 填报者一 | `subsidiary_filler` + `subsidiary_submitter` | 协同编辑、提交（`组织填报人一`，显示名「填报人一」） |
| 填报者二 | `subsidiary_filler` | 同一任务中的第二位协同填报人（`browser-scoped-user-2`，显示名「填报人二」） |
| 审核者 | `department_reviewer` + `report_finalizer` | 审核、退回、定稿、查看报表（`demo-reviewer`） |

- 展示模式只使用一个内部演示组织：所有演示账号的任务、角色和协作房间都落在同一组织下；前端不出现公司名、组织选择器或组织列。
- 周期包只生成一条任务；两名填报人同时指派为 `filler`，各自只能编辑模板中授权给自己的单元格。
- 周期包责任分配必须显式指派填报人、提交人和审核/定稿人，不能依赖默认落到系统管理员。
- 身份在登录页选择；填报提交后的交接按钮可一键切换为审核人，其余情况退出重登。

### 3.2 预置数据

必须准备一份"有故事"的数据，而不是全正常值：

- 1 个已发布模板：3–4 个可编辑字段、1 条业务公式、1 条必填校验、1 个只读单元格、1 列按角色隐藏、1 个签名单元格。
- 3 个任务：待填（已填一半，含 1 个公式阻断 + 1 个预警待说明）、待审、已定稿。
- 上一个月已定稿数据（用于累计值、同比、月报参考）。
- 1 个已发布的月度报表模板 + 1 个生成结果（或现场手动生成）。
- 定时重置 + 页面"重新开始"按钮。

## 4. 引导层需求（已采纳）

### 4.1 演示首页替代账号页

- 每张卡显示状态（未开始 / 进行中 / 已完成）和"开始/继续"按钮。
- 提供"3 分钟快速路线"和"8 分钟完整路线"两个入口（同一版本的两条路径）。

### 4.2 常驻进度条

- 四步导航由演示首页的步骤卡和侧栏「演示主线」承担；顶部演示条已移除，能力标签只保留在演示首页的步骤卡上。
- 当前步骤高亮；已完成打勾。

### 4.3 交接按钮

- 模板发布后："下一步：发起填报任务"
- 周期包激活后："已生成 N 个任务，去填报"
- 提交后："切换为审核者查看结果"
- 定稿后："查看定稿报表"
- 每次交接都带 `taskId`，不要求访客自己找菜单。

### 4.4 任务上下文贯穿

- URL 携带 `taskId` 与 `demoStep`；刷新可恢复。

- 非主线页面不再额外提示；通过侧栏「演示首页」返回即可（2026-11-03 去掉"你正在查看支撑功能"提示）。

### 4.5 能力标注

- 能力标签只保留在演示首页的步骤卡上（Designer / DataManager / OT 协同 / ReportSheet 等）。
- 顶部演示条和页面级"本页能力"标签已移除（2026-11-04）。

### 4.6 术语与文案

- 周期配置包 → 填报计划；报告类型 → 业务类型；修订 → 版本；定稿 → 发布归档；预检 → 提交检查。
- 403 等错误改为面向访客的提示，例如"这一步需要审核者身份，点此切换"。
- 空状态改成"下一步该做什么"，而不是"暂无数据"。

### 4.7 协同提示（替代自动双窗口）

- 保留现有"分享链接"按钮。
- 点击后提示："复制此链接，用另一个账号在另一个浏览器窗口登录，即可体验多人协同。"
- 不做自动第二窗口、不做机器人搭档、不做视频兜底。

### 4.8 结束页与重新开始

- 结束页：能力总结 + 适用场景 + 文档/联系入口。
- "重新开始"：清空本地进度并调用演示数据重置。

| 项 | 原因 |
|---|---|

## 5. 技术实现要点

- **部署形态**：不是静态站点。需要常驻应用服务（Express）、数据库（SQLite，可替换）、WebSocket 协同通道、文件与快照存储；多端读写同一份配置与业务数据。
- **构建开关**：`VITE_SHOWCASE=true`，路由白名单 + 菜单配置化；不 fork 代码、不删业务逻辑。
- **演示壳**：演示首页、下一步交接、任务上下文；重置进度入口放在演示首页底部；能力标签在首页步骤卡上。
- **身份选择**：在登录页选择演示视角；提交后的交接按钮可切换为审核人，其余情况退出后重新登录。
- **路由裁剪**：被移除的页面在 showcase 模式下守卫到演示首页，并提示"该功能不在演示范围"。
- **数据重置**：复用 `server/scripts/reset-demo.cjs` 与 systemd timer；新增一个仅演示环境可用的触发入口。
- **授权**：继续使用 `SPREADJS_LICENSE` / `DESIGNER_LICENSE` 环境变量 + Vite 虚拟模块注入，绝不提交真实授权。
- **并发隔离（待定）**：公开访问时多个访客共享一套库会互相影响。可选方案：
  1. 独立演示实例 + 高频定时重置（最简单）；
  2. 每位访客进入时克隆一份任务/修订（体验最好，开发量中等）；
  3. 单会话排队/锁（体验差，不推荐）。
