成本指标 Demo 的官网化改造

从一个交付给客户的业务系统，改成面向官网访客的 SpreadJS 产品演示。

一句话：这套 Demo 是一条完整的集团报表业务闭环，表格能力全部由 SpreadJS 承担。官网版只保留一条月度主线——设计模板、协同填报、审核发布、报表输出，把治理、季度考核和后台管理收起来；同时补上演示导航与能力标注，让访客 3 分钟看懂、8 分钟走完。
01

Demo 做了什么

STEP 01

设计模板

导入 Excel 或从组件组合成模板，拖入业务字段，配公式与校验，按角色控制单元格的可见与可编辑。

STEP 02

协同填报

多人实时编辑同一张表，提交前自动检查，提交后形成不可变的业务版本。

STEP 03

审核发布

只读快照审核、写意见、退回整改，定稿生成 XLSX、PDF 与结构化数据。

STEP 04

报表输出

ReportSheet 报表、经营指标仪表盘、原始数据导出。

模板的三层结构 业务字段统一口径与类型 → 组件表头 / 表体 / 表尾，可复用 → 模板组合、发布、版本化

底层还有字段目录、规则治理、组织权限、审计等企业级能力，官网版默认收起，销售演示时按需打开。

03

应该给谁看

技术评估

开发者 / 架构师

关心能不能嵌进现有系统、API 是否完整、协同怎么做。重点看设计器、数据绑定、单元格权限和协同实现。

业务决策

财务 / 信息化负责人

关心像不像 Excel、多人能不能同时填、审核有没有留痕。重点看填报体验和审核定稿。

销售开场

合作伙伴 / 售前

需要一个十分钟能讲完的完整故事。用同一套主线做开场，再按客户行业换数据。

04

什么场景适用

  • 集团多组织的月度、季度经营报表
  • 总部下发模板，分支机构填报，总部审核汇总
  • 成本指标、预算与管报、经营分析
  • 任何"Excel 表样 + 多人填报 + 审核留痕"的场景
矿业能源制造业集团交投基建国企央企金融分支政府统计

原方案服务的是矿业和交投类客户。去掉行业专有名词后，能力本身对上述行业是通用的；官网演示用通用指标，销售演示再换行业数据。

05

需要优化和改进

结构：只留一条主线

  • 保留模板设计：Designer、Excel 导入、字段绑定、单元格权限
  • 保留协同填报：实时协同、预检、提交快照
  • 保留审核发布：快照审核、退回、定稿产物
  • 保留报表输出：ReportSheet、仪表盘、导出
  • 收起季度考核、字段与规则审批细节、组织用户管理、历史导入、批量导出

最终保留 86 项、移除 26 项；季度考核整体不做，把故事留给导览和视频。

体验：让访客看得懂

  1. 演示首页 + 四步进度条，四张步骤卡，状态可见。
  2. 每一步一个交接按钮：发布后去发起，提交后去审核，定稿后看报表。
  3. 填报者 / 审核者一键切换，不用重新登录找账号。
  4. 每页标注用到的 SpreadJS 能力，点开有说明和官方文档。
  5. 预置"有故事"的数据：一个公式错误、一个异常预警、一列隐藏、一个签名。
  6. 协同用分享链接，提示用另一个账号登录体验。
  7. 结束页与一键重新开始，形成闭环。
06

和以往 Demo 的不同

以前的 Demo 大多是静态页面，数据写死在前端，放到 CDN 或官网目录就能访问。这个 Demo 的核心卖点是实时协同，它没法静态化。

以往：静态 Demo

  • 无服务页面加本地数据，上传文件即可发布
  • 无状态刷新即重置，多人访问互不影响
  • 不可协同看不到别人在改什么，操作也无法留存

这次：服务 + 数据库

  • 需要常驻应用服务：登录、权限、任务、协同与导出
  • 需要数据库：字段、组件、模板、规则、周期与责任人等配置，以及填报数据，多端读写同一份
  • 需要WebSocket 协同通道：多人编辑实时同步，在线状态与选区可见
  • 需要文件与快照存储：提交快照、定稿的 XLSX/PDF、备份

数据库当前使用 SQLite，随服务部署、零额外运维，后续可替换为 MySQL/PostgreSQL。官网演示需要一个独立部署的服务实例，并配合定时数据重置与备份，不能像静态页一样只传文件。

07

风险与待确认

  • 公开访问的隔离：访客共享一套演示库会互相影响。建议独立演示实例 + 定时重置；体验要求高的话，再考虑每位访客一份任务副本。
  • 进入方式：官网是否免登录直接进入演示，还是保留演示账号一键登录。
  • 脱敏：模板、组织、指标名称是否替换为通用行业词。
