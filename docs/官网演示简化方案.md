> 日期：2026-11-03
> 定位：背景评估与简化原则。**最终范围、实施细节与进度以 `docs/官网演示改造-详细记录.md` 为准。**

## 一、这个项目是什么、能做什么

### 1.1 本质

面向集团型企业的**成本/经营指标报表平台**。核心不是单元格编辑，而是"受控模板 + 组织任务 + 协同填报 + 审核留痕 + 结构化输出"的闭环。SpreadJS 承担其中所有表格能力。

### 1.2 能力清单（以实际用到的为准）

| 能力域 | 具体能力 | 演示位置 |
|---|---|---|
| 模板与设计 | SpreadJS Designer 完整 Ribbon、Excel 导入 / 导出、中文设计器资源 | 报表模板搭建、设计工作台 |
| 数据绑定 | 业务字段、DataManager、CellBindingSource、数模分离 | 设计工作台、填报工作台 |
| 公式与校验 | 公式引擎、异步自定义函数（AsyncFunction）、数据验证、用户公式白名单与引用校验 | 设计器、提交校验 |
| 实时协同 | OT 协作引擎、Presence 在线状态与选区、单元格级协作授权 | 月度协同填报 |
| 单元格权限 | 单元格 Tag、表/行/列/单元格四级权限、按人员/角色/部门、隐藏与脱敏 | 设计器、填报 |
| 签名与呈现 | 手写签名单元格、设计器 PDF 预览 | 设计器、填报 |
| 报表输出 | ReportSheet、PDF 导出与打印、Excel 导出、工作簿 JSON 序列化 | 报表工作室、月度参考报表、审核定稿 |
| 平台能力（非 SpreadJS） | 角色与组织范围、审计、通知、协同服务、数据库持久化 | 全局支撑 |

> 图表与 DataCharts 只在报表设计器里注册了扩展，没有实际实例，**不计入演示能力**。

### 1.3 适合的行业与场景

**直接对口**

- 矿业、能源、化工等多矿/多基地的集团成本报表
- 交通投资、基建类集团：多项目公司向上报送
- 制造业集团：工厂月度经营/成本指标报表
- 国企/央企：月度、季度考核报表与上报

**同构可迁移**

- 财务共享中心 / 预算与管报 / 经营分析
- 保险、银行分支机构的监管报表与业务报表
- 地产多项目公司的项目进度与成本报表
- 政府、园区、事业单位的统计报送

**对外话术**

> 任何「总部下发模板 → 分支机构填报 → 审核汇总 → 出报表」的场景，这套演示都成立。

## 二、为什么原始项目"太复杂"

复杂度不是来自页面数量，而是四层叠加：

1. **角色维度**：13 个角色码 × 组织范围 × 任务责任人，三重校验。访客看不懂"为什么登录进来什么都点不了"。
2. **治理链**：字段 → 模板 → 规则 → 报告类型 → 周期配置包 → 任务，每步都有草稿、审批、版本，冷启动要 10+ 步才能看到协同填报。
3. **状态机**：任务、修订、协同房间、调整申请、季度评分各有一套状态，术语密集。
4. **空数据起点**：分享包不含演示库，访客进来是空库，什么都演示不了。

此外，季度考核、组织管理、历史导入、批量导出、审计等能力对 SpreadJS 卖点贡献很低，却占用大量菜单和认知预算。

## 三、简化目标与原则

**目标**：访客 3 分钟看懂、8 分钟走完主线；每一步都能对应到一条 SpreadJS 能力。

**原则**

1. **只做一个版本**：官网只维护一条主线，不做极简版/复杂版两套。
2. **预置就绪**：不从空库开始；预置模板、组织、任务和数据，提供重置。
3. **角色收敛**：访客只需要"填报者"和"审核者"两个视角，可一键切换。
4. **术语产品化**：周期配置包 → 填报任务配置；修订 → 版本；定稿 → 发布归档。
5. **每步标注能力**：页面标题旁或演示条上标注本页用到的 SpreadJS 能力。
6. **对外脱敏**：去掉客户名、行业专有指标和内部审计信息。

## 四、最终采用的简化方向（方案甲）

- **一条月度主线**：设计模板 → 协同填报 → 审核发布 → 报表输出。
- **保留**：模板设计（Designer、Excel 导入、字段绑定、单元格权限）、协同填报、审核定稿、ReportSheet 报表，以及支撑主线所必需的模板/规则发布、周期配置（含参与组织与责任分配）。
- **移除或收起**：季度考核、组织与用户管理、历史月报导入、批量导出、字段与规则审批细节、自定义角色、版本链，以及未接线的附件上传和批注 @提及。
- **报表怎么体现**：全部走月度主线——报表工作室（ReportSheet）、月度参考报表、已定稿查看、经营指标仪表盘。季度参考报表不进入演示，也不做只读版本；季度能力只在代码中保留，销售演示可按需开启。
- **演示身份**：设计/管理员、填报人、填报人二、审核/定稿，四个视角一键切换。
- **引导层**：演示首页、四步进度条、每步交接按钮、任务上下文、非主线提示、能力标注、故事化预置数据、分享链接提示、结束页、一键重新开始。
- **明确不做**：查看底层抽屉、机器人模拟协同、自动打开第二窗口、视频兜底、额外的首次引导动画。

> 具体保留/移除条目、依赖关系、演示数据与实施进度，见《官网演示改造-详细记录》。

## 六、风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 简化削弱"企业级"卖点 | 收起治理与审批后，大客户可能觉得"只是表格" | 完整能力保留在代码中，销售演示可另行开启 |
| 协同难以现场演示 | 访客不会主动开两个窗口或换账号 | 分享链接 + "用另一账号登录"提示；必要时人工演示 |
| 公开访问并发隔离 | 多个访客共享一套演示库会互相影响 | 独立演示实例 + 定时重置；更高要求时按访客分配任务副本 |
| 授权与环境 | 协同服务端授权绑机器、客户端授权绑域名，换机器或换域名都可能失效 | 固定演示环境，记录机器标识与域名；改授权环境变量后重启后端 |
| 数据被改乱 | 访客提交、审核会改变任务状态 | 定时重置 + 页面"重新开始" |
